# 私聊构建与测试记录

验证日期：2026-10-21。

## 实际执行

- Windows 环境执行 `cmd /c lab1\build.bat`，MinGW-w64 C++17 构建成功，无编译警告；生成 server.exe 和 client.exe。
- 执行 `python lab1/tests/test_private_chat.py`，全部通过。测试启动真实服务器、三个 TCP 协议测试会话，以及 Alice/Bob/Charlie 对应的三个真实 C++ 客户端子进程。
- 定向投递：双方收到相同完整私聊帧，第三方没有私聊帧；真实客户端输出分别为 PRIVATE OUT 和 PRIVATE IN，第三方无私聊输出。
- 中文、英文、正文内部连续空格正确经过 UTF-8 编解码及真实客户端输出。
- 目标不存在、正常退出后离线返回 ERROR；服务器继续处理消息。
- `/msg`、`/msg UIBob`、纯空白正文分别提示用法；随后群聊与私聊正常。
- 畸形负载、尾部多余字节、空白正文和重复私聊序号被拒绝。
- 向自己发送私聊仅投递一次。
- 两个工作线程并发发送共 200 条群聊和 200 条私聊；接收完整帧、数量正确，没有帧交叉。另一个已退出会话不接收这些消息。
- 三个真实 C++ 客户端回归 `/help`、`/list`、`/burst 100`、`/quit`、普通群聊；加入/退出通知及用户列表正常。群聊没有因私聊出现序号缺口报警。

## 检查范围与限制

- 会话快照、shared_ptr 生命周期、发送失败时 shutdown、send_mutex 保护完整帧和 Socket 关闭经过代码检查。
- 未对“目标恰在发送时断开”的所有竞态时机做故障注入；未验证远程网络、防火墙、Wireshark 抓包及人工终端字体呈现。中文验证来自真实客户端输出字节。
- 自动化测试使用空闲本地端口，结束后清理所启动进程；无需占用默认 8888。

复现：先在 `lab1` 执行 `build.bat`，再执行 `python tests/test_private_chat.py`。
